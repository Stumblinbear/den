# Translating messages

## Translate a message for the job it does where it is shown

Read a message together with the messages shown with it, the messages that
refer to the same thing, and the code that renders it. A translation that
reads well on its own can still fail where it is shown. For example, two
labels in a set can shorten to the same letter in the target language, and
then nothing tells their two items apart.

Keep a translation within the limits the project states or a check reports,
such as a maximum length. A limit you only suspect doesn't change the
translation: keep the natural wording and mention the suspected limit in your
report, rather than bending the wording around a limit that may not exist.

## Terms from a domain the project doesn't own

When a message is about something the project doesn't own, such as another
company's product, a game, a sport or a profession, that domain already has
its own words in the target language, and its users expect to see them. Look
those words up. Start with the domain owner's own translation, such as the
product's localized interface. Then search the web for how the domain's
community writes them. If the search turns up no settled usage, say so in
your report.

When the owner's translation covers the message or a term in it, use the
owner's text, even if the community writes it differently, because the
domain's users already know the owner's wording. The owner's text still has
to do the job the message does where this project shows it.

When the owner has no translation for a term, translate it into ordinary
target-language words, the way the owner translates its own terms, rather
than borrowing the foreign word, often English, that the community uses.

Skip the search for names the project made up, such as its own feature names,
and for ordinary sentences. No one outside the project has words for these,
so there is nothing to find.

## The project glossary

Follow the project's glossary when it has one. A glossary entry is for the
thing it describes, not for every message that uses the same word. When a
message refers to that thing, use the entry's term, in whatever grammatical
form the sentence needs. When a message uses the word in another sense,
translate it as that message needs.

When the glossary has no entry for a term, propose one in your report rather
than choosing a translation message by message, so the term reads the same in
every message.
