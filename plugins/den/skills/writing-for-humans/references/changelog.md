# Changelog entries

A changelog entry tells someone who uses the project what changed for them.
They read it to decide whether the change affects them, so say what they will
notice, in one sentence when one is enough:

- **Something new:** what was added and what it is for. `A dark theme, which
  you can turn on in Settings.`
- **A change:** what now behaves differently. `Search results show the newest
  first.`
- **A fix:** what was wrong, as the user saw it. `Fixed exports dropping rows
  that have an empty name.`

Leave out how the change works and what a new thing contains. The diff, the
commit message and the docs hold those, and in the changelog they bury the
one fact the reader came for.

A changelog is where history belongs, so the rule to describe what is rather
than what changed does not apply here: an entry is a description of a change.
